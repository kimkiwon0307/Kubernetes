# Kubernetes 프로젝트 학습

## 1장 1교시 — Docker와 Kubernetes의 차이 및 등장 배경

### 1. Docker란?

Docker는 애플리케이션과 실행에 필요한 환경을 컨테이너 이미지로 만들고, 컨테이너를 실행·관리하는 플랫폼이다.

- **Dockerfile:** 이미지를 생성하기 위한 명령어를 정의한 파일
- **Image:** 애플리케이션 실행에 필요한 파일과 환경을 패키징한 결과물
- **Container:** 이미지를 기반으로 생성·실행되는 격리된 환경

### 2. Docker만으로 운영할 때의 한계

Docker만으로도 컨테이너를 운영할 수 있지만, 여러 서버에서 많은 컨테이너를 관리하려면 추가적인 관리 기능이 필요하다.

- 여러 서버에 컨테이너 배치 및 관리
- 서버 장애 시 다른 서버에 컨테이너 재배치
- 트래픽 증가에 따른 애플리케이션 확장
- 여러 컨테이너의 배포 및 업데이트 관리

※ Docker도 재시작 정책을 지원하지만, 단독 Docker Engine만으로는 여러 노드의 워크로드를 통합 관리하기 어렵다.

### 3. Kubernetes란?

Kubernetes는 컨테이너화된 애플리케이션의 배포, 확장, 운영을 자동화하는 오픈소스 컨테이너 오케스트레이션 플랫폼이다.

**주요 기능**
- **스케줄링:** 적절한 Node에 Pod 배치
- **자동 복구(Self-healing):** 장애 발생 시 컨테이너 재시작 또는 Pod 교체
- **스케일링:** 애플리케이션 복제본 수 조정
- **서비스 디스커버리:** 애플리케이션 간 통신 지원
- **롤링 업데이트:** 서비스 중단을 최소화하는 순차적 업데이트
- **롤백:** 이전 배포 버전으로 되돌리기

### 4. 컨테이너 오케스트레이션

여러 컨테이너의 배포, 배치, 실행 상태, 확장 및 복구를 통합적으로 관리하는 기술이다.

**핵심 개념**

- **Desired State:** 관리자가 원하는 상태
- **Current State:** 실제 현재 상태
- **Reconciliation:** 원하는 상태와 현재 상태의 차이를 줄이는 조정 과정

예시:

```text
Desired State : Pod 3개
Current State : Pod 2개

→ Kubernetes가 부족한 Pod 1개 생성을 시도
→ 정상 조건에서 Pod 3개 유지
```

### 5. Kubernetes 기본 구성

- **Cluster:** Kubernetes가 관리하는 노드들의 집합
- **Control Plane:** 클러스터 상태와 작업을 관리하는 구성요소
- **Worker Node:** 실제 애플리케이션이 실행되는 서버
- **Pod:** Kubernetes에서 컨테이너를 실행하는 기본 배포 단위

### 6. Docker Compose와 Kubernetes 차이

| 구분 | Docker Compose | Kubernetes |
|---|---|---|
| 주요 목적 | 여러 컨테이너 구성·실행 | 클러스터 기반 애플리케이션 운영 |
| 운영 환경 | 주로 단일 호스트 | 여러 노드 |
| 자동 재시작 | 지원 | 지원 |
| 노드 장애 시 재배치 | 기본 지원하지 않음 | 지원 |
| 확장 | 수동 복제본 조정 가능 | 수동·자동 확장 지원 |
| 운영 복잡도 | 비교적 낮음 | 높음 |

**선택 기준**
- 간단한 서비스와 단일 서버 운영 → Docker Compose
- 다중 노드, 자동 복구, 확장 및 복잡한 배포 관리 필요 → Kubernetes 검토

※ Kubernetes가 모든 프로젝트에 필요한 것은 아니다.

### 7. 기본 실습 명령어

```bash
# Nginx 컨테이너 실행
docker run -d --name k8s-intro -p 18080:80 nginx:alpine

# 실행 중인 컨테이너 확인
docker ps

# HTTP 응답 확인
curl -I http://localhost:18080

# 컨테이너 강제 삭제
docker rm -f k8s-intro

# 컨테이너 삭제 여부 확인
docker ps -a --filter name=k8s-intro
```

**실습 목적:** 단독 Docker 환경에서 컨테이너를 삭제하면 자동으로 다시 생성되지 않는다는 점을 확인한다. 이후 Kubernetes Deployment의 자동 복구 동작과 비교한다.

### 8. 면접 핵심 질문 및 답변

**Q1. Kubernetes를 사용하는 이유는?**

여러 서버에서 컨테이너화된 애플리케이션을 효율적으로 운영하기 위해 사용한다. 스케줄링, 장애 복구, 확장, 롤링 업데이트 등을 통해 운영을 자동화할 수 있다.

**Q2. Docker와 Kubernetes의 차이는?**

Docker는 컨테이너 이미지 생성과 실행·관리에 중점을 둔다. Kubernetes는 컨테이너화된 애플리케이션을 여러 노드에 배포하고 원하는 상태를 유지하도록 관리하는 플랫폼이다.

**Q3. Desired State란?**

관리자가 선언한 목표 상태를 의미한다. Kubernetes는 현재 상태를 확인하고 원하는 상태와의 차이를 줄이도록 지속적으로 조정한다.

**Q4. Kubernetes는 반드시 필요한가?**

아니다. 단순한 서비스는 Docker Compose만으로 충분할 수 있다. Kubernetes는 다중 노드 운영, 복구 자동화, 확장 및 배포 관리 요구사항이 있을 때 고려한다.

---

### 핵심 요약

**Docker = 컨테이너 생성 및 실행·관리**

**Kubernetes = 컨테이너화된 애플리케이션의 배포·확장·운영 자동화**

**Kubernetes의 핵심 원리 = Desired State를 선언하고 실제 상태를 지속적으로 조정한다.**
