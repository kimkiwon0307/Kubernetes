# Kubernetes 프로젝트 학습
## 3장 2교시 — Pod 생명주기, 재시작 정책, 멀티 컨테이너

### 1. Pod 생명주기 (Lifecycle)

Pod는 생성부터 종료까지 여러 상태를 거친다.

| Pod Phase | 의미 |
|---|---|
| Pending | Pod가 생성되었지만 컨테이너 실행 준비가 끝나지 않음 |
| Running | Node에 배치되어 컨테이너가 실행 중이거나 시작·재시작 중 |
| Succeeded | 모든 컨테이너가 정상 종료 |
| Failed | 모든 컨테이너가 종료되었고 하나 이상 실패 |
| Unknown | Pod 상태 확인 불가 |

**중요**
- `CrashLoopBackOff`: 컨테이너가 반복적으로 종료되어 재시작을 지연하는 상태
- `ImagePullBackOff`: 컨테이너 이미지 다운로드 실패 후 재시도를 지연하는 상태
- 위 두 가지는 Pod Phase가 아니라 `kubectl get pods`에 표시되는 상태 사유이다.

### 2. restartPolicy — 컨테이너 재시작 정책

| 정책 | 정상 종료 | 비정상 종료 | 사용 예 |
|---|---|---|---|
| Always | 재시작 | 재시작 | Nginx, Spring Boot |
| OnFailure | 재시작 안 함 | 재시작 | 실패 시 재시도하는 작업 |
| Never | 재시작 안 함 | 재시작 안 함 | 일회성 작업 |

YAML 예시:

```yaml
spec:
  restartPolicy: OnFailure
```

**핵심 원리**
- kubelet이 Pod 내부 컨테이너의 재시작을 관리한다.
- containerd가 실제 컨테이너를 실행한다.
- 컨테이너 재시작은 기존 Pod 안에서 이루어진다.
- 삭제된 Pod를 새로 생성하는 것은 Deployment 등의 컨트롤러 역할이다.
- 단독 Pod를 삭제하면 `restartPolicy: Always`여도 자동 재생성되지 않는다.

### 3. emptyDir — 임시 공유 볼륨

`emptyDir`는 Pod에 생성되는 임시 볼륨이다.

```yaml
volumes:
  - name: shared-html
    emptyDir: {}
```

**특징**
- 같은 Pod의 여러 컨테이너가 함께 사용할 수 있다.
- 컨테이너가 재시작해도 파일이 유지된다.
- Pod가 Node에서 제거되면 데이터가 삭제된다.
- 영구 저장이 필요한 MySQL 데이터에는 적합하지 않다.

### 4. 멀티 컨테이너 Pod

하나의 Pod에 여러 컨테이너를 실행하는 구조이다.

**실습 구성**

```text
Pod: multi-demo
│
├── Nginx 컨테이너
│   └── 웹 페이지 제공
│
├── Writer 컨테이너
│   └── 5초마다 HTML 파일 생성
│
└── emptyDir 공유 볼륨
    └── index.html
```

**핵심 원리**
1. 같은 Pod의 컨테이너는 Pod IP와 네트워크 네임스페이스를 공유한다.
2. 따라서 `localhost`를 이용해 컨테이너끼리 통신할 수 있다.
3. 동일한 볼륨을 마운트하면 파일을 공유할 수 있다.
4. 각 컨테이너는 별도의 프로세스와 파일시스템을 사용한다.
5. 보조 컨테이너가 메인 애플리케이션을 지원하는 구조를 사이드카 패턴이라고 한다.

**공유 볼륨 예시**

```yaml
volumeMounts:
  - name: shared-html
    mountPath: /shared
```

Writer가 `/shared/index.html`을 생성하면, 같은 볼륨을 `/usr/share/nginx/html`에 마운트한 Nginx가 해당 파일을 제공할 수 있다.

### 5. 핵심 실습 명령어

**Pod 생성**

```bash
kubectl apply -f batch-pod.yaml
kubectl apply -f restart-pod.yaml
kubectl apply -f multi-pod.yaml
```

**Pod 상태 확인**

```bash
kubectl get pods -o wide
kubectl describe pod restart-demo
```

**이전 컨테이너 로그 확인**

```bash
kubectl logs restart-demo --previous
```

- `--previous`: 직전에 종료된 컨테이너의 로그 확인
- 재시작 전 오류를 분석할 때 사용

**멀티 컨테이너 로그 확인**

```bash
kubectl logs multi-demo -c nginx
kubectl logs multi-demo -c writer
```

- `-c`: 로그를 확인할 컨테이너 지정

**컨테이너 내부 파일 확인**

```bash
kubectl exec multi-demo -c writer -- cat /shared/index.html

kubectl exec multi-demo -c nginx -- cat /usr/share/nginx/html/index.html
```

**컨테이너 간 localhost 통신 확인**

```bash
kubectl exec multi-demo -c writer -- \
  wget -qO- http://127.0.0.1:80/
```

### 6. 공통 장애 대응 공식

**상태 → 상세 → 로그 → 원인 → 검증**

① 상태 확인

```bash
kubectl get pods -o wide
```

② 상세 정보·이벤트 확인

```bash
kubectl describe pod <Pod이름>
```

③ 컨테이너 로그 확인

```bash
kubectl logs <Pod이름>
```

멀티 컨테이너인 경우:

```bash
kubectl logs <Pod이름> -c <컨테이너이름>
```

④ 원인 분석 및 수정

- 이미지 또는 설정 오류인가?
- 컨테이너가 종료되었는가?
- 공유 볼륨에 문제가 있는가?
- 네트워크 또는 시스템 자원 문제인가?

⑤ 정상 복구 확인

```bash
kubectl get pods -o wide
```

**장애별 주요 확인 사항**

| 장애 | 중점 점검 |
|---|---|
| CrashLoopBackOff | 이전 컨테이너 로그, 종료 코드 |
| ImagePullBackOff | Events, 이미지 이름·태그·인증 |
| 멀티 컨테이너 오류 | 각 컨테이너 로그, 파일 공유 |
| Node NotReady | Node 상태, kubelet·containerd |

※ 컨테이너가 실행된 적이 없다면 애플리케이션 로그가 없을 수 있으므로 Events를 우선 확인한다.

### 7. 확인문제 핵심 답변

**Q1. restartPolicy의 종류와 차이는?**

Always는 종료 원인에 관계없이 재시작하고, OnFailure는 비정상 종료 시 재시작하며, Never는 재시작하지 않는다.

**Q2. kubelet과 containerd의 차이는?**

kubelet은 Pod와 컨테이너의 실행 상태를 관리하고, containerd는 실제 컨테이너를 실행한다.

**Q3. emptyDir는 무엇인가?**

같은 Pod에 속한 컨테이너들이 공유할 수 있는 임시 볼륨이다. 컨테이너 재시작 시 유지되지만 Pod가 Node에서 제거되면 삭제된다.

**Q4. 멀티 컨테이너 Pod의 특징은?**

여러 컨테이너가 하나의 Pod IP를 공유하고, 필요한 경우 볼륨을 함께 사용하여 협력한다.

**Q5. 멀티 컨테이너 장애 대응 방법은?**

Pod 상태와 이벤트를 확인한 후 `kubectl logs -c`로 각 컨테이너의 로그를 구분하여 확인하고, 필요하면 `kubectl exec -c`로 내부 파일과 통신 상태를 검증한다.

---

### 최종 핵심 암기

1. **Lifecycle:** Pod의 생성부터 종료까지 상태 변화
2. **Always:** 컨테이너 종료 시 재시작
3. **OnFailure:** 비정상 종료 시에만 재시작
4. **Never:** 컨테이너를 재시작하지 않음
5. **kubelet:** 컨테이너 재시작 관리
6. **emptyDir:** Pod 내부 임시 공유 볼륨
7. **멀티 컨테이너:** Pod IP 공유, 볼륨 공유 가능
8. **logs -c:** 특정 컨테이너 로그 확인
9. **logs --previous:** 이전 컨테이너 실행 로그 확인
10. **장애 대응:** 상태 → 상세 → 로그 → 원인 → 검증

**이번 교시에서 가장 중요한 개념**

> kubelet은 재시작 정책에 따라 Pod 내부 컨테이너를 재시작하고, 같은 Pod의 컨테이너들은 네트워크와 지정된 볼륨을 공유할 수 있다.
